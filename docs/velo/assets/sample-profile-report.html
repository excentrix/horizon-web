VELO · examiner

Your README says the limiter is a token bucket at 100/min. In rateLimiter.js the bucket lives in a module-level object. What happens when two requests hit different server instances in the same second?

Candidate A

Each instance has its own bucket in memory, so both would be allowed — the limit is really per-instance, not global. I didn’t handle the multi-instance case.

VELO · examiner

Honest read. How would you make it global, and what does it cost?

Candidate A

Move the counter to Redis with atomic INCR and an expiry. Cost is a network round-trip per request, and Redis becomes a dependency you have to keep available.

VELO · examiner

Right. At 50× the traffic that Redis key becomes a hot spot. How do you keep rate-limiting correct without a single key bottlenecking?

Candidate A

Honestly, I haven’t dealt with that. You’d maybe shard the key — but I’m not sure how you’d keep the global count accurate once it’s split.
